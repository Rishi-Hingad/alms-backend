1. Overview

This API lets the SAP team push vendor lifecycle events into the Remittance Tool so the local Remittance Vendor master stays in sync with SAP.

What's new in v1.1 (2026-06-11)
  • Full set of SAP technical field names (LIFNR, NAME, BEZEI, REGIO, STCD3, J_1IPANNO, VGCLASS, STR_SUPPL1…3, STREET, LOCATION, CITY1, POST_CODE1, COUNTRY, TELF1, TELF2, SMTP_ADDR, REMARK, ERDAT, BUKRS, ZCOUNT, WAERS, KTOKK, J_1KFTIND, ZTERM, TEXT1, AKONT) are now accepted directly — no need to translate to English labels before posting.
  • block_vendor and unblock_vendor now also accept SAP raw field names (e.g. send LIFNR+BUKRS instead of vendor_code+c_code).
  • New SAP Mapper doctype (Desk → SAP Mapper → Remittance Vendor) lets the dev/admin add or change field aliases at runtime — no code deploy needed. Cache auto-invalidates on save.
EndpointMethodPurpose
upsert_vendorPOSTCreate new vendor or update existing (idempotent)
block_vendorPOSTMark vendor as disabled (soft block)
unblock_vendorPOSTClear the disabled flag
upsert_vendorGETReachability ping (no auth)
Vendor identity is composite: (vendor_code, c_code).
The same vendor_code can exist under different c_code (company codes) — these are distinct records. Both fields are required for every operation.

Base path

/api/method/remittance_tool.remittance_tool.api.v1.vendor.<endpoint>

2. Authentication setup

Step 1 — Get API Key & Secret

  1. Login to Frappe Desk as the SAP service user (e.g. sap-sync@meril.local).
  2. Top-right avatar → My Settings → scroll to API Access.
  3. Click Generate Keys. Copy the api_key and api_secret immediately — secret is shown only once.

3. Common response envelope

Every write endpoint returns the same shape. HTTP status is always 200 — inspect the body's status / failed fields.

{
  "message": {
    "status": "success",        // "success" | "partial" | "failed"
    "count": 2,
    "succeeded": 2,
    "failed": 0,
    "results": [
      { "status": "success", "vendor_code": "V0001", "c_code": "1000",
        "name": "V0001-1000", "action": "created", "ignored_fields": [] },
      { "status": "success", "vendor_code": "V0002", "c_code": "1000",
        "name": "V0002-1000", "action": "updated", "ignored_fields": [] }
    ]
  }
}
FieldMeaning
statussuccess = all rows ok · partial = some failed · failed = all failed
actioncreated · updated · blocked · unblocked
ignored_fieldsPayload keys that didn't match any known vendor field (debugging aid)
Per-row commits: Every row is committed independently using a savepoint. A single bad vendor in a bulk batch fails alone — the rest of the batch still saves.

5. Field mapping (SAP → Remittance Tool)

The API accepts SAP-style column headers and our internal snake_case names. Matching is case-insensitive; _, ., and spaces are normalized.

SAP / payload keyStored as
LIFNR, Vendor, vendor codevendor_code
NAME, Name, NAME1, vendor namevendor_name
BEZEI, Statestate
REGIO, State Codestate_code
STCD3, GSTN No, GST Nogstn_no
J_1IPANNO, PAN No, PANpan
VGCLASS, Vendor GST Classificationvendor_gst_classification
STR_SUPPL1, Address01address01
STR_SUPPL2, Address02address02
STREET, Address03address03
STR_SUPPL3, Address04address04
LOCATION, Address05address05
CITY1, City, Town City Districtcity_district
POST_CODE1, Pincode, Pin Codepincode
COUNTRY, Country (name / ISO code / country code)country (resolved against Remittance Country master)
TELF1, Contact Nocontact_no
TELF2, Alterenate No, Alternate Noalternate_no
SMTP_ADDR, Email-Id, Email Idemail_id
REMARK, Remarkremark
ERDAT, Created On (YYYY-MM-DD, DD-MM-YYYY, DD/MM/YYYY, YYYYMMDD)created_on
BUKRS, C.Code, C Codec_code  [required, part of unique key]
ZCOUNT, Countcount
WAERS, Currencycurrency
KTOKK, Account Groupaccount_group
J_1KFTIND, Type of Industr, Type of Industrytype_of_industry
ZTERM, Payment Term, Terms of Paymentterms_of_payment

AKONT, Reconciliation Acco, Reconciliation Accountreconciliation_account
Runtime-configurable mappings: the dev/admin can add or change aliases without a code deploy — open Desk → SAP Mapper → Remittance Vendor and edit the table. The cache invalidates automatically on save, so the new alias takes effect within seconds. Use this when SAP introduces a new column or renames one.
Unknown keys are silently dropped and reported in ignored_fields per row. If you see your field name there, the alias is missing — raise it with the dev team, or add it directly in SAP Mapper.

6. Error reference

Error messageMeaning & fix
Authentication required (HTTP 401)Basic Auth header missing/wrong. Re-check api_key/api_secret.
Vendor code is requiredPayload missing Vendor / vendor_code.
Company Code (C.Code) is requiredPayload missing C.Code / c_code. Both fields form the composite key.
Vendor name is required for new vendor X/1000New record but no Name field.
Country '...' does not exist in Remittance CountryCountry master must contain the value (by name, code, or ISO). Add to master first.
Vendor V123 (C.Code 1000) not foundBlock/Unblock target doesn't exist with that key combo.
Duplicate entry '...' for key 'PRIMARY'Schema not reloaded after autoname change. Run: bench --site <site> reload-doctype "Remittance Vendor"
ignored_fields: [...] in resultPayload key not recognized. Either typo or alias missing — check Section 5.

Server-side traces: For deeper debugging, every per-row failure logs a full traceback under Desk → Error Log with title Vendor API error (...).

7. SAP event → endpoint recipe

SAP event / transactionCall this endpoint
Create new vendor (XK01)upsert_vendor
Update vendor (XK02)upsert_vendor
Block vendor (XK05, XK06)block_vendor
Unblock vendorunblock_vendor
All endpoints are idempotent — safe to retry the same payload after a failure or timeout. No duplicate records will be produced.

8. cURL examples — for terminal/scripted tests

Alternative to Postman. Replace BASE_URL, API_KEY, API_SECRET with your values.

8.1 Reachability ping (no auth)

curl -X GET \
  "$BASE_URL/api/method/remittance_tool.remittance_tool.api.v1.vendor.upsert_vendor"

8.2 Upsert — single vendor (SAP raw payload)

curl -X POST \
  "$BASE_URL/api/method/remittance_tool.remittance_tool.api.v1.vendor.upsert_vendor" \
  -u "$API_KEY:$API_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "LIFNR": "0000010602",
    "NAME": "TEST STCD5",
    "BEZEI": "24-Gujarat",
    "REGIO": "06",
    "STCD3": "0",
    "VGCLASS": "Registered",
    "STREET": "VAPI",
    "CITY1": "VAPI",
    "POST_CODE1": "396102",
    "COUNTRY": "IN",
    "TELF1": "9899999999",
    "SMTP_ADDR": "STCD5@MERIL.COM",
    "ERDAT": "2025-07-14",
    "BUKRS": "7000",
    "WAERS": "INR",
    "KTOKK": "ZMAT",
    "ZTERM": "T028",
    "AKONT": "0013301700"
  }'

8.3 Upsert — bulk (from file)

Save batch as vendors.json, then:

curl -X POST \
  "$BASE_URL/api/method/remittance_tool.remittance_tool.api.v1.vendor.upsert_vendor" \
  -u "$API_KEY:$API_SECRET" \
  -H "Content-Type: application/json" \
  --data-binary @vendors.json

8.4 Block vendor (SAP raw keys)

curl -X POST \
  "$BASE_URL/api/method/remittance_tool.remittance_tool.api.v1.vendor.block_vendor" \
  -u "$API_KEY:$API_SECRET" \
  -H "Content-Type: application/json" \
  -d '{ "LIFNR": "0000010602", "BUKRS": "7000", "reason": "Tax hold" }'

8.5 Unblock vendor

curl -X POST \
  "$BASE_URL/api/method/remittance_tool.remittance_tool.api.v1.vendor.unblock_vendor" \
  -u "$API_KEY:$API_SECRET" \
  -H "Content-Type: application/json" \
  -d '{ "LIFNR": "0000010602", "BUKRS": "7000" }'
Auth tip: curl -u "$API_KEY:$API_SECRET" sends Authorization: Basic <base64> automatically. No need to construct the header by hand.
